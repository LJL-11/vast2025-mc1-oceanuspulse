# 前端数据契约 v1.1.0

负责人：邬昊文。数据生成命令：`python -m pipeline.run`。默认目录：`data/processed/`。默认截点：赛题中的 2040 年；默认 seed=42。

v1.1 在原有字段上新增三份分析产物，默认总数为 84。适配器接受 `1.x.x`，但同一次加载中的每个文件必须与 manifest 的精确小版本、输入、截点和种子一致。

## 1. 共同约定

- 每份 JSON 有 `meta`：`schema_version`、`source_sha256`、`observation_year`、`cutoff_year`、`seed`。不要混合不同来源、截点和种子的产物。
- 节点 `id` 是原始整数 ID；名字不唯一。边 `id` 为字符串 `原始source:原始target:key`，跨文件保持一致。
- 年份为整数，未知为 `null`；部分不适用的字段（如 Person 的发行年）不出现。零计数是 `0`，未知时差/分母为零的比例是 `null`，不能统一渲染成 0。
- `type` 统一代替原始 `Node Type` / `Edge Type`。作品日期映射为 `release_year` / `written_year` / `chart_year`。
- 完整规范图、质量审计和节点索引保留最终观察到的全部证据，**不等于历史快照**。历史模型只取按 cutoff 重算的 features、dated events 和投影指标。
- `notable` 为是否登上热门榜单，不是排名第一；不能绘制不存在的精确销量、播放量、排名数据。
- `manifest.json` 包含参数、软件版本、输入文件哈希以及各产物的 path/bytes/sha256；完整验证用 `python -m pipeline.validate`。

## 2. 最小接入示例

为避免踩到前端共享代码，本分支把适配器放在 `pipeline/examples/`。组长整合时，可在现有 `web/vite.config.js` 增加插件：

```javascript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { pipelineDataPlugin } from '../pipeline/examples/vite-data-plugin.mjs'

export default defineConfig({
  plugins: [vue(), pipelineDataPlugin()],
  base: './',
})
```

它在 dev 时提供 `data/` 下的 JSON，在 build 时作为静态资产输出到 `dist/data/`。只复制页面需要的文件和艺人分片，不复制原始数据、全量工程图、质量报告、冗余全量 features/timelines。构建前必须先运行 Python 管线，源文件与 manifest 不符会报错。

模块三既有的 `rising_star.json` 使用独立契约，不在这 84 份数据工程产物内。其页面默认请求 `${BASE_URL}data/processed/rising_star.json`；适配器会把该请求交给后续静态文件服务。按模块三原有方式运行 `python pipeline/features.py`，再把该文件放到 `web/public/data/processed/rising_star.json`（或由组长配置独立的静态资源服务），无需修改模块三页面。数据工程适配器不会自动复制该独立分析文件。

从 `web/src/lib/dataService.js` 接入浏览器侧服务的示例：

```javascript
import { createDataService, expandAnnual } from '../../../pipeline/examples/data-service.mjs'

export const dataService = createDataService({
  baseUrl: `${import.meta.env.BASE_URL}data/`,
})
export { expandAnnual }

// 页面按需使用；不要在根组件一次性请求所有文件。
const overview = await dataService.overview()
const ego = await dataService.sailorEgo()
const sailor = await dataService.artist(17255)
const annual = expandAnnual(sailor.timeline)
```

适配器按 manifest 的 schema/来源/截点/seed 检查版本，缓存请求，失败后允许重试。网络图方法返回独立副本，避免 D3 修改 `source/target/x/y` 后污染其他视图。`clearCache()` 用于切换整套数据。若加入 history 路由，部署者需同步配置正确的项目 base。

上面的示例是接入说明；本分支没有擅自改动 `web/vite.config.js` 或公共组件。Vite 相关行为依据 [官方插件 API](https://vite.dev/guide/api-plugin.html)。

## 3. 文件、顶层键与加载时机

| 文件 | 主要顶层键 | 使用场景 |
|---|---|---|
| `overview.json` | counts、year_fields、chart_status、issue_counts、components、graph_sizes、genre_work_counts | 首屏总览和数据范围提示 |
| `network_overview.json` | nodes、links | 600 节点以内的初始概览；焦点两跳优先，然后按全图度补足 |
| `sailor_ego.json` | nodes、links | 完整 Sailor 两跳布局，默认 269 节点 / 546 边 |
| `sailor_shift.json` | focus_id、works、collaborators、memberships、ego、inspiration_sources、directly_influenced、upstream_paths、downstream_paths、events | 模块一详情与关系证据 |
| `node_index.json` | nodes | 按 ID 查名字、艺名、类型、作品流派；不带全图边 |
| `influence_events.json` | events | 音乐影响证据钻取，含过滤标记及原始端点 |
| `influence_evidence.json` | events、summary、focus | 将明确艺人引用和作品署名归属分开，提供原始边证明路径 |

## 4. 网络坐标和方向

结构图节点示例形状：

```typescript
type Node = {
  id: number; type: 'Person' | 'MusicalGroup' | 'RecordLabel' | 'Song' | 'Album';
  name: string; display_name: string; stage_name?: string;
  genre?: string; release_year?: number | null; chart_year?: number | null;
  notable?: boolean; quality_flags: string[];
  x: number; y: number;  // 只有带布局的图文件包含坐标
}
type RawLink = {
  id: string; source: number; target: number; key: number;
  type: string; quality_flags: string[];
}
```

`network_overview` 和 `sailor_ego` 的边**保留原始关系方向**，不能把每一个箭头都标为“影响”。例如 `PerformerOf` 是艺人→作品，`InStyleOf` 是借鉴作品→来源。不同关系类型需要不同的图例。

`x/y` 来自 Python 的 100 次迭代 spring layout，各连通分量分别布局并装入网格。浏览器可直接画线和点，支持缩放/拖拽；无需开启全图 force simulation。概览是有偏的上下文选取，meta 中有 omitted_node_count，不能用它代替全图算指标。完整两跳 ego 单独导出，不被 600 节点概览预算裁剪。

## 5. 音乐影响事件与路径

`influence_events.events[]` 的字段：

| 字段 | 含义 |
|---|---|
| id、type | 原始关系 ID 与五类音乐引用类型 |
| source、target | **来源 → 受影响者**，与该关系的原始方向相反 |
| raw_source、raw_target | 可直接回查 MC1_graph.json 的原始端点 |
| year、year_basis | 借鉴作品发行年代理；艺人间无日期关系为 null / unknown |
| source_genre、target_genre | 两端为作品时的直接 genre；不为艺人擅自推断流派 |
| eligible_dated | 可进入当前截点年度分析 |
| eligible_structural | 可进入结构性影响路径；无日期关系只用于 2040 完整观察 |
| quality_flags | 时间顺序、自环、重复或官方端点模式差异 |

年度图使用 `eligible_dated === true`。不能先把 null 年份补成零再交给时间轴。

`sailor_shift.works` 按发行年、ID 排序，给出本人直接署名作品及 roles。`collaborators` 按共同作品数降序，包含 `work_ids/first_year/last_year`；不把前乐队成员自动视为共同参与了每首作品。

`inspiration_sources`、`directly_influenced` 提供相连引用事件数及 event_ids，包含无日期直接关系，因而不能直接当作年度序列。`upstream_paths/downstream_paths` 提供每个可达节点的一条确定性最短路径，字段为：`id/hops/seed_id/node_path/event_ids/event_years/fully_dated`。种子是本人及所有直接署名作品；最大三跳，只沿音乐影响边，不沿录制、发行或普通合作边。上游路径沿追溯方向走，边 ID 仍保持原始身份。

这是可核查的结构可达性，不是因果传播证明，也不是枚举所有可能路径。

## 6. 流派流向与趋势

`genre_flows.flows[]`：

```typescript
type GenreFlow = {
  year: number;
  source: string; target: string; // 来源流派 -> 受影响流派
  type: string;                 // 可筛选 InStyleOf 等关系
  value: number;                // 引用事件条数
  source_work_count: number; target_work_count: number;
  event_ids: string[];
}
```

同一作品对可能同时有 CoverOf 和 InStyleOf，所以聚合关系时要区分“事件数”和“独立受影响作品数”。跨多个 flow 的 `target_work_count` **不能直接相加去重**，应沿 event_ids 取事件 target 集合。

```javascript
const { flows } = await dataService.genreFlows()
// Oceanus Folk 影响外界：source = Oceanus Folk；吸收外界：target = Oceanus Folk。
const outward = flows.filter(d => d.source === 'Oceanus Folk' && d.target !== d.source)
// 若页面只讲风格继承，进一步筛 type === 'InStyleOf'；默认统计包含全部五类。
```

`genre_trends.rows[]` 每个 year/genre 唯一：

| 字段 | 含义与分母 |
|---|---|
| work_count、song_count、album_count | 当年发行作品数，Song/Album 分开，避免把二者当同一歌曲重复推断 |
| new_chart_entries_known_date | 当年首次登榜事件数，仅显式日期 |
| observed_notable_releases | 在 2040 被标为 notable 的作品，按发行年分组；不是当年登榜事件；历史截面为 null |
| outbound_events、inbound_events | 本流派向外、外界向本流派的引用事件，不含流派内部 |
| internal_events | 同一流派内部引用 |
| all_cross_genre_events_in_year | 当年全部跨流派事件的分母 |
| outbound_share | outbound_events / all_cross_genre_events_in_year；分母 0 时 null |
| external_influenced_work_count | 当年发行的外流派作品中，至少一次借鉴本流派的独立作品数 |
| all_external_work_releases | 当年所有其他流派新发行作品数 |
| external_work_coverage | 上述独立受影响作品数 / 外流派新发行数；分母 0 时 null |
| outbound_trailing_5y_mean | 截至当年的后向五年平均；序列开头按实际年数计算 |

趋势文件的流量指标聚合全部五种关系；若 UI 切换为 InStyleOf-only，需从 flows 同步重算分子和分母，不能沿用默认比例。

## 7. 艺人分片、特征和三人对比

分片规则：`id % 64`，文件名补两位。`17255 % 64 = 39`，所以 Sailor 位于 `artists/39.json`。每片大约数百 KiB。`artistIndex()` 只用于搜索，`artist(id)` 返回：

```typescript
type ArtistDetail = {
  features: Record<string, unknown>;
  metrics: Record<string, unknown>;
  timeline: {
    id: number; year_range: [number, number];
    annual: Array<Record<string, number>>; // 稀疏：仅事件年份
    works: Array<{ id: number; year: number; genre: string; roles: string[]; chart_year_as_of: number | null }>;
  };
}
```

关键特征字段：

| 类别 | 字段 |
|---|---|
| 身份与观察期 | id/name/type，first_release_year，last_release_year，career_years_observed，years_since_last_observed_release |
| 产出与身份 | work_count、song_count、album_count、performed_work_count、roles、work_ids、performed_work_ids |
| Oceanus Folk 关联 | oceanus_work_count 为所有四类署名；oceanus_performed_work_count 只计直接表演 |
| 流派跨度 | genre_count、genres（流派→作品数）、genre_entropy（log2 Shannon entropy） |
| 动态产出 | recent_5y_work_count、previous_5y_work_count、productivity_change、recent_work_share |
| 合作变化 | collaborator_count、recent_5y_collaborator_count、new_5y_collaborator_count |
| 已知登榜 | known_charted_work_count、first_known_chart_year、years_to_first_known_chart、median_known_chart_lag、known_chart_lag_sample_size |
| 最终快照标签 | observed_notable_work_count、undated_notable_work_count，仅 cutoff=2040 时可用 |
| 音乐影响 | influence_credit、recent_5y_influence_credit、influence_event_ids；明确表演者分摊，非人气 |

`first_release_year` 基于所有四类直接署名，表示首个**观察到的**作品。Song 和 Album 作为两个作品实体保留；原数据没有提供每首歌属于哪张专辑的完整结构，不能擅自消重为“唯一歌曲产量”。

轨迹包含自然年 `year` 和职业相对年 `career_year`，可分别比较同一时代或出道后第几年。`expandAnnual()` 对空年将年度新增补 0、累计值向前延续；这只是该数据内无观测事件，不推断艺人停产。已知登榜时差必须搭配样本数与缺失信息展示。

指标中 `raw_*` 是完整证据图统计。`collaboration_*` 和 `influence_*` 是按 cutoff 的相应投影统计。`collaboration_betweenness` 是抽样近似值，不能当精确排名；不支持通过前端年份刷选即时重算。

## 8. 候选排序展示规则

`rising_star_baseline.candidates[]` 包含 rank、id/name/type、score、contributions、work_ids、influence_event_ids、最近观察年份。`score` 是 0–1 的人为加权相对分，不是预测概率。contributions 每项包含 value、percentile、weight、contribution，和为 score。

- 同分名次相同，不通过 ID 偷偷决定胜负。
- `meta.constant_features` 列出候选间没有区分力的特征；不要据此宣称某候选影响更大。
- `activity_filter_sensitivity` 对比无活跃期限制、近 3 年、近 5 年的候选数量。
- 若选定筛选后不足 3 人，应展示数量不足，不能自动补足或编造三人预测。
- 页面应注明“探索性候选排序，待模块三验证”。正式 Top3 的标准、稳健性检验、预测结论由模块三报告负责。

## 9. 错误、验证与复现

运行整条管线会验证原始文件未变、关系端点存在、原属性未丢失、flow 证据不重不漏、进出流量守恒、职业累计值一致、布局坐标有限且无悬空边，以及分片完整覆盖。

如果修改单个生成文件或只运行某一个中间脚本，manifest 可能与内容不一致。请重新运行完整 `python -m pipeline.run`；不要手改生成 JSON 后将其当作分析证据。

复现需要相同输入 SHA-256、cutoff、seed、参数和依赖版本。`requirements.txt` 锁定 NetworkX/NumPy/SciPy；输入、运行版本、生成物哈希都可在 manifest 核对。没有生成时间戳，便于逐文件比较。

## 10. v1.1 影响证据

```javascript
const evidence = await dataService.influenceEvidence()
const incoming = evidence.focus.incoming // 归属到艺人的来源关联
const outgoing = evidence.focus.outgoing
```

events 与旧 `influence_events.events` 一一对应，新增：

| 字段 | 含义 |
|---|---|
| evidence_kind | `explicit_artist_reference` 为原图明确记载的艺人间引用；`work_attribution` 为通过作品署名推导的艺人联系；`mixed_attribution` 支持作品与艺人之间的引用 |
| source_credits、target_credits | 每个归属艺人的 artist_id、work_id、roles、edge_ids；默认只认明确 PerformerOf |
| observable_at_cutoff | 两端作品在截点之前可见；时间疑点对照也不允许使用未来端点 |

focus 的 incoming/outgoing 按关联艺人分组；explicit_reference_count 与 attributed_reference_count 分开，dated_count 与 undated_count 分开。`fractional_attributed_weight` 只累计作品归属推导的分摊量，不与直接关系相加。所有 event_ids 保留，example_paths 最多三条，并用 omitted_example_count 说明未展示数量。

每条路径含 `node_path/steps/event_id/evidence_kind/year`。steps 的 edge_id 都是原始边，traversal 为 forward/reverse，分别表示顺着或逆着原始方向沿证据路径行走。作品归属不证明个人交往、因果传播或实际影响强度；艺人间无日期关系仍为 null。

## 11. v1.1 年度和滚动指标

```javascript
const dynamics = await dataService.networkDynamics()
const sailor = dynamics.artists.find(d => d.id === 17255)
const row2035 = sailor.rows.find(d => d.year === 2035)
// 折线图读取每年的 cumulative.collaborator_count，或 rolling.collaborator_count。
```

默认对比对象为焦点艺人、原乐队成员和最多十位候选；2040 默认运行得到 12 人、2024–2040 的艺人年度数据。可用 `--compare-ids 17349 17355` 补充对象。meta.cohort 记录选择依据及省略数量。MemberOf 只帮助选择上下文，不产生作品署名和成员日期。按最终截点选对象再回看过去，是回顾性比较，不是无偏预测回测。

每位艺人的 rows 从其首个直接署名作品年开始，包含：

| 对象 | 字段 |
|---|---|
| cumulative | work_count、collaborator_count、collaboration_pagerank、collaboration_pagerank_percentile、known_charted_work_count、collaborator_genre_count、outside_own_genre_collaborator_count、dated_influence_credit、dated_influenced_artist_count、influence_source_pagerank、influence_source_pagerank_percentile、cross_genre_influence_credit、cross_genre_target_count |
| rolling | start_year/end_year、observed_dataset_years、work_count、collaborator_count、new_collaborator_count、dated_influence_credit |
| annual | new_work_count、new_collaborator_count、new_dated_influence_credit、collaborator_change_yoy；首次观察年份的同比为 null |

指标每年在**完整的当年可见网络**上重算，最后只导出有限对比对象。不能把对比对象的子图中心性当成全图中心性。合作 PageRank 百分位在当年的全部直接署名艺人中计算；影响来源百分位只在有正向有日期引用证据的来源艺人中计算，没有该类证据为 null。百分位采用并列中秩，不是成名概率。

rolling 的新合作者指首次共同署名发生在窗口内；过去合作过、窗口内再次合作的人只算活跃合作者。窗口内的新引用允许借鉴窗口之前的老作品，不应把老作品随窗口一起删除。`--window-years` 只调整这个产物，原有 recent_5y 特征仍固定五年。

genre_windows 覆盖 1975–cutoff，每个流派/年一行。包含滚动 outbound/inbound/internal 事件数、全球跨流派分母、outbound_share、去重受影响作品数、外部目标流派数和与前一非重叠窗口的差值。observed_years 与 previous_observed_years 记录数据跨度覆盖；未覆盖完整两窗时差值为 null。计数变化不自动构成爆发性传播或显著性结论。

## 12. v1.1 敏感性报告

```javascript
const report = await dataService.robustness()
// 展示不同定义的比较，而不是自动挑一套最符合预期的排名。
const rules = report.influence_scenarios
const candidateWeights = report.candidate_weight_scenarios
```

影响规则共有七种：基准、纳入时间疑点、InStyleOf-only、三类录音复用、不含歌词引用、各关系类型等总量、四类创作署名归属。每项给出权重、事件数、分摊量、艺人与流派排名对照。艺人比较指标是有日期引用的分摊量，流派比较指标是外向跨流派加权事件数；两者都不是人气。

comparison 包含 spearman（仅相关系数）、top_set_jaccard、基准/对照 top 集合、进入/离开集合与最大名次变化。共同为零的对象不参与影响排名相关系数；常量或样本不足为 null。Top-k 边界有并列时**全部保留**，unique_top_k_set=false，不能按 ID 裁成固定人数。空集合的相似度为 null，不报告虚假的完全稳定。

候选权重共有五套，候选集合固定，给出常量特征所占权重、分数、并列名次和 Top3 集合。相似度高不代表可以唯一选三人；当前五人并列第三的结果会使 Top3 边界集合包含七人。方法、范围和真实结果见 [优化说明](07-数据工程优化与稳健性.md)。
