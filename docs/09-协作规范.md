## 一、核心原则：分层所有权

冲突的根因不是「人多」，而是「大家都改同几个文件」。按层划清归属后，多数 PR 天然不冲突。

| 层 | 文件 | 归属 | 规则 |
| --- | --- | --- | --- |
| **Shell 层（冻结）** | `web/src/App.vue`、`web/src/styles/main.css`、`web/src/stores/useAppStore.js`、`web/src/lib/dataService.js`、`web/vite.config.js`、`web/index.html`、`web/package.json` / `package-lock.json` | 组长（付嘉一） | **组员禁止修改**。需要加 Tab、加全局状态、加依赖，在 PR 描述里提需求，由组长统一改一次并立刻 push |
| **视图层（自由）** | `web/src/views/InfluenceTrace.vue`（01）、`GenreSpread.vue`（02）、`RisingStar.vue`（03）、`NetworkOverview.vue`（00） | 各模块负责人 | 随便改，但**一个 PR 只提交自己负责的那一个 view 文件** |
| **组件层（先说一声）** | `web/src/components/*` | 谁用谁改 | 改共享组件的 props / 事件名之前在群里说一声，并自查所有引用处 |
| **数据层（只增不删）** | `pipeline/`、`data/raw/`、契约 JSON 字段、`web/src/lib/dataService.js` | 邬昊文 + 组长 | 契约字段**只增不删**；删/改字段必须全组同步并跑 `node --test pipeline/tests/frontend.test.mjs` |
| **交付层** | `report/`、`docs/03-设计手绘/`、`docs/04-会议记录.md`、本文档 | 隋咏轩 + 组长 | 系统变更后同步更新；与系统描述不一致时以 `main` 为准 |

**主题红线**：保持白底学术蓝。任何 PR 不得引入 `data-tone="dark"`、全局 `body` / `:root` 背景覆盖，或整套覆盖 `main.css`。00 的样式一律用独立命名空间（如 `op-overview-*`），不得写全局选择器。

## 二、组员每次提 PR 前必做

```bash
git fetch origin
git rebase origin/main               # 关键：先站到最新 main 上再开发/提交
git push -f origin <自己的分支>       # rebase 后强推自己的分支；永远不要强推 main
```

- 分支命名：`feat/<模块>-<简述>`，例：`feat/module2-evidence-panel`。
- **一律从最新 `main` 拉分支**。不要基于 `feat/competition-interface` 继续开发。
- 一个 PR 只解决一件事；描述里写清：改了哪些文件 / 有没有动数据口径 / 截图 / 本地 `npm run build` 结果。
- 本地先跑：`npm run build` + `node --test pipeline/tests/frontend.test.mjs`。

> ⚠️ **`feat/competition-interface` 分支即日起弃用**。它基于 `0587531`，含整套暗色重写和旧版 01/02/03；
> 谁基于它开新分支，PR 会把旧代码一起带回来，必然冲突。该分支仅作 00 代码的取料来源，取完即归档，不再更新。

## 三、组长合并前的检查清单

```bash
git fetch origin
git log --oneline main..origin/<branch>              # 看提交范围
git diff --name-only main...origin/<branch>          # 重点：有没有碰 Shell 层
git diff --stat main...origin/<branch>               # 改动面是否异常（>10 文件要问原因）
```

- 出现 `App.vue` / `main.css` / `vite.config.js` → **打回**，让对方 rebase 后重新只提交自己的文件。
- 确实需要部分采纳时，**不点 GitHub 的 Merge 按钮**，改为按文件摘取：

```bash
git checkout origin/<branch> -- web/src/views/GenreSpread.vue
# 本地 build + 浏览器验证 → 单独 commit → push
```

- 若 `App.vue` 仍冲突：一律**以 main 为准**（保住流光表头），把对方新功能以「新增组件 + 新增 Tab」的方式手动接进来。
- 每次合并后组长立刻 push，并在群里发最新 commit hash；所有人以该 hash 为基线 rebase。

## 六、冲突预案（一句话）

| 情况 | 处理 |
| --- | --- |
| 又来一个「全量重写」PR | 不合并，按文件摘取 + 本地验证 + 组长单独提交 |
| `App.vue` 冲突 | 以 main 为准，新功能手动接成新增组件 / 新增 Tab |
| 两人同时改了同一个 view | 先合的为准，后合的 rebase 后手动并内容，不覆盖 |
| 数据契约被改 | 打回；契约字段只增不删，需全组同步 |
| 主题被改成深色 | 打回；主题是课程交付物一致性的一部分 |
